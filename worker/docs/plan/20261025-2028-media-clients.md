# 20261025-2028-media-clients Make the media library a standalone library published per client URL

- **status**: completed
- **createdAt**: 2026-10-25 20:28
- **approvedAt**: 2026-10-25 20:40
- **relatedTask**: 20261025-2028-media-clients

## Context

- **How the media library is coupled to tvbox today:**
  - It is served only under a tvbox device's subscription: `/s/<device token>/media/*` (`workers/subscription.ts` → `workers/media/handleMedia`).
  - The Worker finds the device in the tvbox devices file in R2, then hands over to the media code.
  - Uploaded images are rewritten to the device's tvbox file mirror (`/s/<token>/a/…`).
  - tvbox entries reference the library through the `@media/` placeholder (`MEDIA_PLACEHOLDER`), which the subscription rewrites to the device's own URL.
  - Publishing the tvbox config also publishes the library (`tvbox/publish.service.ts` → `markPublished`).
- **What the dropped plan would have added:** `20261025-0248-media-channels` planned to tie visibility to tvbox devices, with a device channel and the devices table moving to D1. That would have deepened the coupling.
- **User decision (2026-10-25):**
  - The media library is a general content library, not built around our own client. It publishes media to different clients, each through its own URL.
  - tvbox is one independent consumer that references a client URL.
  - The two systems share only the admin console.
  - `20261025-0248-media-channels` is dropped.
- **What is already independent:** the library's data already lives only in D1 (`tv-bk-io`, binding `MEDIA`), and the Worker answers `/media/*` straight from it (`20261025-0124-media-serve-from-source`). Only the entry point, asset URLs, publish gating and the tvbox placeholder are coupled.
- **What stays in tvbox:** `/s/<token>/media/home` (the TMDB recommendation home) belongs to tvbox, not to the library, and stays where it is.

## Proposal

### 1. Media clients (D1)

- **Migration** `d1/media/0004_clients.sql`:

  ```sql
  CREATE TABLE media_clients (id TEXT PRIMARY KEY, name TEXT NOT NULL, token_hash TEXT NOT NULL UNIQUE,
    token TEXT, enabled INTEGER NOT NULL DEFAULT 1, note TEXT NOT NULL DEFAULT '', created_at TEXT NOT NULL, updated_at TEXT NOT NULL);
  CREATE TABLE media_channels (id TEXT PRIMARY KEY, name TEXT NOT NULL, sort INTEGER NOT NULL DEFAULT 0, created_at TEXT NOT NULL, updated_at TEXT NOT NULL);
  CREATE TABLE media_client_channels (client_id TEXT NOT NULL REFERENCES media_clients(id) ON DELETE CASCADE,
    channel_id TEXT NOT NULL REFERENCES media_channels(id) ON DELETE CASCADE, PRIMARY KEY (client_id, channel_id));
  CREATE TABLE media_title_channels (title_id TEXT NOT NULL REFERENCES media_titles(id) ON DELETE CASCADE,
    channel_id TEXT NOT NULL REFERENCES media_channels(id) ON DELETE CASCADE, PRIMARY KEY (title_id, channel_id));
  CREATE INDEX idx_media_title_channels_channel ON media_title_channels (channel_id);
  ALTER TABLE media_titles ADD COLUMN public INTEGER NOT NULL DEFAULT 0;
  DROP TABLE media_published;
  ```

- **A client** is a named consumer with its own secret token, kept like tvbox device tokens: the hash for lookup, plus the token so the console can show the URL again. A client can be enabled, disabled, rotated and deleted.
- **A channel** is a content partition. A channel sees nothing by default.
- **Which clients see a title:**
  - a title marked `public` is visible to every client;
  - any other title is visible only to clients subscribed to one of its channels;
  - a title that is neither public nor in a channel is visible to no client;
  - seasons and episodes follow their title.
- **Every client belongs to at least one channel.**
  - Creating or updating a client without a channel answers 422.
  - Deleting a channel that is the only channel of a client answers 409 `CHANNEL_IN_USE`.
- **Imports:** `POST /media/import` takes an optional `public` flag that it sets on the titles it writes. The import script and workflow pass it on with `--public`, so the 4944 imported titles can be made public by re-running the import. New and existing titles are otherwise not public.
- **Live:** live channels and EPG are visible to every client.

### 2. Client URLs (Worker)

- **Routes:**
  - `/m/<client token>/v1/*` — the native Media API;
  - `/m/<client token>/cms` — the Apple CMS site;
  - `/m/<client token>/live.m3u` — the live playlist;
  - `/m/<client token>/a/<sha256>/<name>` — uploaded images, served from R2 by content hash.
- **Handling:** the Worker looks the client up in D1 by token hash and caches it per isolate for 10 s. It answers 404 for an unknown or disabled client and never touches the tvbox devices file.
- **Queries:** `LIVE_TITLE` becomes:
  - `publish_state = 'published'`;
  - a series also needs a published season;
  - the title is public or in one of the client's channels.

  `loadSlice`, the CMS playable query, and the person and collection queries take the client's channel set.
- **Cache:**
  - The shared cache key is the path without the token, plus the generation, plus the client's sorted channel ids. Clients with the same channels share entries.
  - The ETag follows the same key.
  - Playback stays `no-store`.
- **Asset placeholders:** `@a/` placeholders are rewritten to the client's own `/m/<token>/a/`.

### 3. Publishing and generation

- **Publish gate:** `media_published` and `markPublished` go. A title, season or episode is live when its `publish_state` is `published`.
- **Generation:** `media_settings.generation` is bumped by one middleware on the media admin router after every successful non-GET request, so changes show at once.
- **No generation yet:** `/m/*` treats it as `"0"`, so there is no `NOT_PUBLISHED` state.
- **tvbox publishing:** `tvbox/publish.service.ts#publish` publishes only the subscription config again.

### 4. Decoupling tvbox

- **Removed:**
  - the `/s/<token>/media/*` route (except `/media/home`);
  - `MEDIA_PLACEHOLDER` (`@media/`) and its rewrite;
  - the media import in `workers/subscription.ts`;
  - the `markPublished` call from tvbox publishing.
- **How tvbox references the library:** like any other source. A site entry's `api` is a media client URL, for example `https://tv.bk.io/m/<token>/cms`. Different device groups can get different clients through tvbox's existing per-upstream and common entries. The media console's publish tab offers the URLs to copy, instead of adding `@media/` entries.
- **Production:**
  - existing tvbox entries that still contain `@media/` stop resolving;
  - these are entries created from the publish tab (`own_media` site, `自有直播` live), and the console lists them so they can be repointed;
  - the library is not live in production yet, so no device loses working content.

### 5. Console (one admin UI, separate sections)

- **Media → Clients:**
  - list, create, rename, enable or disable, rotate the token, delete;
  - pick the client's channels;
  - copy the v1, CMS and M3U URLs.
- **Media → Channels:** a list of channels (name and sort).
- **Title editor:** a "public" switch and a "channels" multi-select. A title with neither is visible to no client.
- **Publish tab:** replaced by the Clients tab. Status copy says titles go live when they are published.
- **tvbox pages:** unchanged.
- **Locales:** zh and en.

### 6. Tests and verification

- **New tests first (RED):**
  - client lookup: unknown, disabled and rotated tokens answer 404;
  - visibility: public titles, channel titles, titles in neither, and a client on another channel, across browse, search, detail 404, CMS category, facets and person;
  - a client cannot be saved without a channel, and a client's last channel cannot be deleted;
  - an import with `public` marks its titles public;
  - assets are served by hash under `/m/<token>/a/`;
  - two clients on the same channels share a cache key, and clients on different channels do not;
  - the generation is bumped by admin writes.
- **Ported tests:** `publish.test.ts` is removed. `media.test.ts` and `cms.test.ts` call the client entry instead of the subscription. The subscription tests lose the media cases.
- **Gates:** `bun run check`; then `bun run test:workers`, where the smoke test creates a client and a restricted title, reads v1, CMS and M3U through the client URL, and checks that `/s/<token>/media/v1` is gone.
- **Production:** deploy (manual dispatch), create the first client in the console, and check v1, CMS and M3U against the 4944 imported titles.

## Risks

- **Old URLs stop working:** device configs that referenced `@media/` lose those entries until they are repointed to a client URL. The library has not been published in production yet, so nothing that works today breaks.
- **Migration:** `0004` drops `media_published`. It is forward-only, and the code shipped with it does not read that table.
- **Token secrecy:** client URLs carry a bearer token. Anyone who has the URL can read that client's catalogue, the same exposure as a tvbox subscription URL today. Rotating the token cuts them off.
- **Cache churn:** every console save bumps the generation and empties the shared cache for all clients. This is acceptable for a catalogue that rarely changes.
- **Query cost:** two `EXISTS` subqueries per title on small, indexed tables. Unrestricted titles short-circuit them.

## Alternatives

- **Keep serving under the tvbox subscription and add per-device channels:** this is the dropped plan, rejected by the user because it couples the two systems.
- **Visibility per client directly** (a title lists clients, with no channels): this is simpler, but every new client needs every restricted title re-assigned. Channels keep it one step.
- **A public media API without tokens:** anyone could then read the catalogue and the stream URLs. Not chosen.
