## Context

- **Origin.** `worker/` was imported in `4ded7f9` (2026-10-03) as a trimmed, Workers-only copy of [zzci/bun-tpl](https://github.com/zzci/bun-tpl). The import did not record a template commit.
  - Comparing the shared files (`shared/`, `modules/account`, `db/`, web components and lib) against template history puts the base at `c6f5c58` (2026-09-29, "ci: pin runners to ubuntu-26.04"). That is the closest match: 68 differing lines over 85 files, all from later worker edits.
  - No template sync has happened since then.
- **Template changes since the base.** The template has 32 commits up to `25c3463` (2026-10-24): 319 files, +10.4k/−3.2k lines.
  - 175 of the changed files exist in the worker.
  - The rest are in modules the worker dropped (item, document, issue, policy, cron, encryption, lode), plus e2e tests and Docker/lode deployment.
- **Applicability.** Patches were checked per commit with `git apply --check --directory=worker`. Most of them apply only partly, because the worker has since:
  - rewritten `workers/entry.ts`;
  - added its own root download page and `BASE_PATH` handling;
  - edited account routes and locales;
  - added the tvbox and media modules.

## Proposal

## Verification

- **Per group:** `bun run check` (lint, typecheck, unit tests with the coverage gate, build, i18n, env and API docs drift).
- **At the end:** `bun run test:workers`, the smoke test on workerd, covering login, console SPA, subscription and media.
- **Manual check:** the TOTP QR renders (uqr) and API tokens can be renamed and rotated in the console, checked against the local dev server.

## Risks

- **TypeScript 7.0:** the native compiler may report new errors in worker-only code (tvbox, media, workers). These are fixed in place as part of this task.
- **The `reasonable-newline` style:** it reformats many worker files, producing a large mechanical diff. It goes in its own commit so reviews and blame stay readable.
- **Database migrations:** password accounts and token rotation add DO SQLite migrations, generated with the worker's own drizzle numbering after `0013`, not copied from the template. They are forward-only.
- **Sessions and audit:** the sliding-session and trusted-proxy changes touch auth on every request. They are covered by the ported unit tests and the smoke login case.
- **Commit split:** the work goes in as several commits (fixes, account, refactors, docs, deps, style), so any group can be reverted on its own.

- **Root:** `package.json`, `bun.lock`, `eslint.config.ts`, `.env.example`, `.gitignore`, `packages/tsconfig`, and `.github/workflows/worker.yml`.

## Alternatives

- **Re-import the template and re-apply the worker's changes on top:** the worker's own changes far outweigh the template delta, so this costs more and risks more. Not chosen.
- **Port only fixes and dependency bumps:** smaller, but the next sync keeps growing. It remains an option if the account features are not wanted.
